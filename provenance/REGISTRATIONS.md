# Registrations and how to check them

Paths are relative to the repository root. This text was part of the README until the commit that added this file.

## Registrations

Every registration and blind prediction in the paper was committed and pushed to GitHub before the data it concerns was read, except where the paper's Appendix E.12 says otherwise: its paragraphs on the prediction rounds give each round's exceptions (B1, for example, was made after the E0a results it predicts had been committed), and its paragraph "Slips in the registration record" collects the others. Tables 11 and 12 (Appendix E.10) and Appendix E.12 say what each prediction is blind to.

The paper cites the commit hashes of the original development repository. That repository stays private, because four of its notes files hold information about other people and an unrelated project; this repository is the same history, without six commits that hold nothing cited (five of a side branch and GitHub's test merge commit for an unmerged pull request from it), and with those passages and a clause in each of two commit messages redacted, five local tool-configuration files removed and an older name and e-mail address of the first author replaced by a mailmap (`provenance/REDACTIONS.md`), so its commit hashes differ. No code, experiment configuration, registration or data file differs in any commit of that history, except the redacted notes files that two registrations include (*How to check*, item 2, below).

The first public-release commit of `trap/arxiv` (tag `trap-arxiv-v1`; the paper's Appendix E.13 calls it "a final release commit") rewords or removes a few lines in the notes and Slurm comments, replaces another allocation's account name in the tests with a placeholder (so three checks that no Slurm directive or runbook names that account now always pass), and adds a fallback to the freeze check in `analysis/theory/pred2/common.py`, which compares against tag `r13-theory-pred` when the original commit is absent; `provenance/REDACTIONS.md` describes all of its changes, and `git show --name-status trap-arxiv-v1` lists the files it adds (A) and edits (M). Later public-release commits on `trap/arxiv` change only documentation: the first rewords the README, `provenance/REDACTIONS.md` and `provenance/registration-proofs/README.md`, and the second rewrites the README, moves this text here from it and updates two items of `provenance/REDACTIONS.md`.

## How to check

1. **Tags.** `git tag -n99 -l 'r*' 'icml-*'` lists the frozen tags with their messages, and `git for-each-ref --format='%(refname:short) %(taggerdate:iso)' refs/tags` their tagger times. The frozen tags' names, messages and tagger times are identical to the original tags; only the commit they point to differs, so each tag object, like its commit, has a new hash (`provenance/commit-map-public.tsv` lists both). The five `archive/*` tags are original tags as well, with the same names, messages and tagger times; the mailmap normalized their tagger's name and e-mail address (*Provenance* below); `verify.py` does not check them. `trap-arxiv-v1` and `arxiv-v1` are this repository's release tags and have no original. The messages are as written at the freeze and are not corrected afterwards: the message of `r13-theory-pred2` says pred2 was frozen before any N2 job, but the N2 runs (the closed H200 runs at n = 36, 44 and 52, jobs 17169612-17169614) had ended before its push, as the dated erratum at the end of `notes/PREDICTIONS_r13_pred2.md` (`bf19385`; `bb3dff7` here) and the paper's Appendix E.12 say.
2. **Registration content.** In a POSIX shell, `git show trap-arxiv-v1:configs/agentload_prereg_2026-10-24.yaml | sha256sum` gives the SHA-256 printed in the paper's Appendix E.11. Hash the committed bytes this way: `sha256sum` of a checked-out file gives a different value wherever Git converts line endings on checkout (the Git for Windows default, `core.autocrlf=true`). Appendix E.11 also prints the vLLM registration's SHA-256 and names the tags whose messages give the SHA-256 of their files. Two of those messages give only the first eight hex digits for some files: `r11-lpminf-pred` for its registration (`f4454c5b`), and `r11-basin-reg` for its two cell configs (`3fd25217`, `967d9bbf`) and its frozen endpoints `configs/r11_basin_predict.yaml` (`2f340909`, given in full in the messages of `r14-basin2-reg` and `r14-extra-reg`); `git show <tag>:<path> | sha256sum` gives the full value. `verify.py` (item 4) checks every registered file against its original commit except the redacted notes files that two registrations include (`notes/STATE.md` for the native rate rule; `notes/LOG.md`, `notes/STATE.md` and `notes/STATE_h200.md` at `r15-reg`), which it reports as differing by design.
3. **Push times.** `provenance/github-activity-2026-11-06.json` is an export of GitHub's activity log for the original repository (`gh api --paginate repos/AkshatValse/Nova-Research/activity`), and `provenance/ls-remote-2026-11-06.txt` a `git ls-remote` snapshot of it taken when this repository was built. Reviewers can get read access to the original repository to see the same log on GitHub. GitHub logs branch pushes, not tag pushes, so each tag is dated by the first push whose new tip contains the tagged commit.
4. **Old to new hashes.** `provenance/commit-map-public.tsv` maps every original commit of the published branches and tags, and every tag of the original repository, to this repository's; the public-release commits (the tip of `r10/arxiv`, and on `trap/arxiv` the commit tagged `trap-arxiv-v1` and every commit after it) are new and are not in it. `python provenance/registration-proofs/verify.py` recomputes each original commit hash from its raw object, follows the parent chain to the commit GitHub recorded, and checks that the original `configs/`, `prereg/`, `src/`, `results/`, `analysis/` and `slurm/` trees, the registered files other than the redacted notes files of item 2, the commit dates and messages, the mapped parents and the tags (apart from the commit each points to) are identical to this repository's. Because this history was rewritten with a mailmap (`mailmap_applied` in `provenance/registration-proofs/proofs.json`), it does not compare author, committer and tagger names and e-mail addresses; those of every registration commit and frozen tag are unchanged, as the stored original objects in `provenance/registration-proofs/objects/` show.
5. **Slurm job IDs.** The job logs under `results/nova/**/` print, for each Slurm job, the job ID and the commit it ran at (an original hash; look it up in the commit map). Submit, start and end times of the jobs are recorded by Iowa State's Slurm accounting, a third party.
6. The 103 commits made before 2026-10-22 17:45 CDT come from an earlier repository (`provenance/commit-map.tsv`). The earliest push record of 98 of them is the original repository's first push to GitHub, at 17:45:50 CDT that day, or one 2 s later; the other five are reachable only from `archive/*` tags, which have no push record. No registration is among them.

## Provenance
This history has been rewritten twice. Both rewrites kept every commit of the branches and tags published here, with its author, committer, dates, tags and parent relations, except that the public release gave the 111 commits of 2026-10-20 to 2026-10-23 and the five `archive/*` tags, which in the original record the first author under another name and e-mail address, the name and GitHub noreply address that every later commit and tag here uses (a mailmap; `provenance/REDACTIONS.md`). The original's other branches and its pull-request refs are not published (README, *Branches and tags*).
1. **2026-10-22**, when the work moved from the earlier private repository `jannesari-swapp`: only commit-message trailers changed (co-author trailers were removed). Every file tree is identical. Notes and `meta.json` files from before then cite the original hashes; look them up in `provenance/commit-map.tsv` (columns: `old`, `new`).
2. **Public release**: this repository was built from a mirror of the private development repository `AkshatValse/Nova-Research` by redacting passages of four files in `notes/`, removing five local tool-configuration files from every commit and replacing an older name and e-mail address of the first author by a mailmap (`provenance/REDACTIONS.md`). Commit and tag messages are unchanged, except 2 commit messages in which a clause about the same redacted topics was replaced by a marker (listed in `provenance/REDACTIONS.md`). In every rewritten commit every other file keeps its hash: every code, configuration and data blob, and every registered file except the redacted notes files that two registrations include (item 2 of *How to check* above). The public-release commits on top of this history (the tip of `r10/arxiv`, and on `trap/arxiv` the commit tagged `trap-arxiv-v1` and every commit after it) are new commits that, between them, add files and edit a few (*Registrations* above; `provenance/REDACTIONS.md`). The paper, the notes and the job logs cite the development repository's hashes; `provenance/commit-map-public.tsv` maps them to this repository's, and `provenance/registration-proofs/verify.py` checks the correspondence for every registration.
